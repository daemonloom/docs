Read the result correctly​

The list is an effective task catalog, not a list of everything installed or detectable. In the active design, an operation reaches that list only when its provider, datasource, boundary, endpoint grant where applicable, owner facts, operation identity, and effect all match the immutable profile.

A Connector-backed datasource is stricter still: it needs a surfaced endpoint with an active grant, a connected owner state, and current authorization. The design makes revocation monotonic so recompilation removes the endpoint's operations and rediscovery cannot silently reactivate it.

Recipes are starting shapes, not authority​

The four recipes answer “what kind of work is this?” They do not grant access. A real product still needs to bind the selected work mode to an exact workflow, worker route, capability ceiling, approval posture, limits, evaluation, and evidence requirements.

The longer-term product direction makes those bindings versioned Work Modes. It also supports two collaboration postures: an autonomous posture in which the harness may observe admitted state and propose useful work, and a prompt posture in which the engineer normally initiates it. That initiative never expands authority. Work Mode execution and the autonomous proposal experience remain design work, not current released functionality.
