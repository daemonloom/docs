Copy a task recipe for Zwirn

A useful work packet names the outcome, admitted inputs, allowed effects, stop condition, and completion evidence. The recipes below are practical framing templates; they are not installed Work Modes and grant no capability.

Product pre-v1Work controllable dev coreDefault bounded

What is selectable today​

--activity-mode prompt|autonomous selects one of two implemented built-in workflows. Prompt mode waits for your task. Autonomous mode may propose a Goal from already admitted observations. Neither changes the workspace, operations, worker, network, or effect ceiling.

Understand, Change, Operate, Respond, and Decide below are task recipes, not selectable product modes. A future capitalized Work Mode is a versioned installed binding of workflow, activity posture, worker/model defaults, capabilities, approvals, budgets, evaluation, and visible controls.

Only the first recipe fits today's native workspace.status surface without additional selected Connector reads. The other recipes teach the intended task contract and remain future product experience where they require file access, mutations, or production systems.

Understand a failing release​

Outcome:      Explain the release failure without retrying it.
Inputs:       Release identifier, admitted CI reads, and source/revision observations.
May do:       Read only; correlate exact returned facts.
Must not:     Retry, push, deploy, change configuration, or infer unavailable file contents.
Stop when:    The cause is evidenced, a required source is absent, or mutation is the next step.
Done means:   Supported cause, ruled-out hypotheses, citations, and safest next action.

If retry is not present in the effective capability surface, approval cannot create it. Finish with the diagnosis or start new work after an owner makes an exact operation available.

Change a bounded code path​

Outcome:      Fix the parser regression without changing the public contract.
Inputs:       One writable worktree and the repository's documented checks.
May do:       Edit parser code/tests and run already admitted local checks.
Must ask:     New dependency, network access, another repository, push, release, or deploy.
Stop when:    The cause is outside the worktree or acceptance criteria conflict.
Done means:   Focused diff, relevant passing checks, changed artifacts, and remaining risk.

This is a future ordinary-workspace recipe. The current worker's private directory does not mount the selected project and Zwirn does not yet surface general edit/test operations.

Investigate or respond to an incident​

Outcome:      Explain elevated checkout latency and prepare the safest mitigation.
Inputs:       Severity/scope, time window, admitted telemetry/deploy reads, current owner facts.
May do:       Read and correlate; append attributed facts and hypotheses.
Must ask:     Traffic shift, feature disable, rollback, scaling, or wider system access.
Stop when:    Evidence is sufficient, the time box ends, or a new boundary is required.
Done means:   Timeline, strongest hypothesis, mitigation option, verification plan, and handoff.

Approval for a mitigation proves only that the exact action may run. Completion requires a Connector/provider result and a separately observed recovery signal. If the response is lost after the request crossed the effect boundary, record outcome unknown and inspect provider state before retrying.

Compare an architecture decision​

Outcome:      Choose between two migration paths against reliability and delivery constraints.
Inputs:       Named architecture records, operational evidence, deadlines, and non-negotiables.
May do:       Read, compare, identify assumptions, and request missing evidence.
Must ask:     New private source, experiment, publication, implementation, or budget increase.
Stop when:    Criteria separate the options or a bounded unresolved question remains.
Done means:   Comparison matrix, recommendation, supporting facts, and open assumptions.
