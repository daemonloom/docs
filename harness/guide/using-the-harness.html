Run Zwirn locally

This is the current source-installable development path: install Zwirn beside the separately released Substrate daemon, start a prompt-led session, inspect its exact operation surface, and exercise steering, narrowing, approval, cancellation, and evidence.

Product pre-v1Work controllable dev coreDefault bounded
Development build

There is no stable public binary channel or compatibility promise. The commands below are for an authorized Agent source checkout. The current worker starts in an empty private directory: the workspace is observed, but it is not mounted into the model process. General project file access, editing, tests, terminal, diff, preview, and production operations are not available yet.

1. Check the prerequisites​

The current installation path requires:

  • Linux with the separately built, compatible substrate-daemon already on PATH;
  • Rust/Cargo and Task for source installation;
  • the exact supported Codex CLI for both routes;
  • an existing Codex login for the default authenticated route; and
  • a disposable or deliberately scoped workspace for evaluation.

From the Agent checkout:

command -v substrate-daemon
codex --version
task install
zwirn --version

task install installs only the zwirn command. Missing or incompatible Substrate and Codex artifacts refuse; Zwirn does not substitute direct host execution, another worker, or another inference route.

2. Start one prompt-led session​

Use the authenticated Codex route:

zwirn --cwd /absolute/path/to/workspace --activity-mode prompt

Or exercise deterministic provider compatibility without paid inference:

zwirn --cwd /absolute/path/to/workspace \
  --activity-mode prompt \
  --inference-route fixture

The fixture is still a development conformance path and still needs the exact Codex and Substrate artifacts. It does not silently replace a failed authenticated route.

For the local browser surface:

zwirn --cwd /absolute/path/to/workspace --activity-mode prompt web
# Do not open a browser automatically:
zwirn --cwd /absolute/path/to/workspace --activity-mode prompt serve

Both commands bind IPv4 loopback only and print a private bootstrap URL, rendered API documentation, and /openapi.json. Do not share the bootstrap URL: its fragment is the session capability.

3. Send a task the current surface can answer​

The native development surface exposes a bounded, shell-free workspace.status operation. A useful first task is therefore deliberately modest:

Outcome:      Report the admitted workspace status and explain the limits of your evidence.
Scope:        The exact workspace selected at startup.
May use:      workspace.status only.
Must not:     Infer file contents, run a shell, use the network, or claim a repository diagnosis.
Stop when:    The operation returns or the current profile refuses it.
Done means:   The observed status, its evidence owner, and every unanswered question.

After you select a supported Connector Endpoint, a task may also use the exact read operations surfaced for it. Do not put passwords, API keys, private keys, reusable bearers, daemon URLs, or raw provider endpoints in the prompt.

4. Verify the preflight​

Before dispatch, inspect these concrete facts:

ViewExpected current fact
Workspacethe exact --cwd; parent directories were not searched
WorkerCodex is explicitly selected and matches the supported profile
Inferencecodex/authenticated or the explicitly selected codex/fixture
Operationsworkspace.status, plus only the selected Endpoint reads that current owner facts admit
Workspace accessno project mount inside the worker's private directory
Effectsread-only in the built-in local profile
Evidenceoperation results retain their native or Connector owner; worker statements remain worker-reported

/profile, /tools, and /endpoints open the current effective surface. An observed resource or Connection candidate with no surfaced operation is information, not authority.

5. Use the implemented controls​

IntentTUI controlExact behavior
Inspect current authority/profile, /tools, /endpointschanges the view; grants nothing
Inspect attributed facts/evidenceshows the evidence matrix/timeline
Narrow the local operation surface/surface workspace.status offremoves the operation immediately
Restore that ceiling-owned operation/surface workspace.status onproposes the exact digest-bound restoration for approval
Accept or reject a pending decision/approve or /denyresolves only the currently correlated request
Change the next step inside the same boundarysend another messagesteers active work; it cannot widen the profile
Stop active work/cancelrequests cancellation; wait for terminal acknowledgement
Start without conversation context/new or /clearreleases the Codex thread and private directory; revoked authority stays revoked
Change the visible panelCtrl-Btoggles the sidebar
Exit/quitcancels active work first instead of abandoning it

Repeated prompts reuse one Codex thread, but every turn receives a fresh Agent-owned governed run and a fresh operation session. Conversation continuity therefore does not preserve stale operation admission.

6. Read refusals as useful output​

SymptomMeaning and action
substrate-daemon cannot be resolved or admittedinstall the exact supported artifact or pass its path/socket; there is no direct-host fallback
Codex is absent or has another versioninstall the pinned version; Zwirn does not select Claude or a fixture automatically
workspace.status disappearsthe effective profile was narrowed; inspect /profile and restore only through the correlated proposal
A detected source has no operationdetection did not create a Grant; inspect the selected Connection and owner admission
A hosted operation refuseshosted selection is catalog-read-only today; broader task wording cannot manufacture Connector invocation authority
Cancellation remains pendingthe request is recorded, but terminal worker/execution evidence has not arrived yet
A mutating provider response is losttreat the outcome as unknown; inspect provider state before considering a retry

7. Check the completion record​

For the first task, a credible terminal record contains:

EvidenceWhat to require
Resultthe bounded workspace-status observation, not an inferred repository analysis
Operationexact operation id, target, provider, and completion/refusal state
Provenancewhich facts came from Agent, the worker, Connectors, or Substrate
Decisionsany exact profile delta and its approve/deny result
Limitselapsed time and known or unknown usage/bounds
Uncertaintyfiles, checks, external systems, and outcomes that were not observed
