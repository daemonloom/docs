00 / ENGINEERING PATHS

Pick the problem.
Declare the boundary.

The harness is one work surface across code and systems. Each task still declares what may change, what needs approval, and which evidence makes it complete.

01Frame the work

Turn a problem into a bounded engineering task

Name the objective, systems in scope, allowed changes, decision points, and evidence that would make the result credible.

objective → scope → completionOpen guide ↗
02Software work

Shape repository work as an attributable task

Bind the objective, workspace posture, authority, capabilities, and lifecycle limits before the coding loop starts.

understand → change → verifyOpen guide ↗
03Systems work

Investigate infrastructure through governed operations

Search, inspect, and invoke admitted external operations without handing credentials or raw endpoints to the model.

observe → correlate → decideOpen guide ↗
04Live work

Control long-running tasks and incident work

Follow ordered output, pause for consequential actions, steer the active turn, cancel cleanly, and retain terminal evidence.

01 / EXECUTION SEAM

One work surface.
Independent controls.

The coding harness compiles one task-fit boundary and holds the live engineering loop. Agent makes the run controllable. Connectors governs external systems. Substrate bounds the runtime and workspace. The operator sees one experience without those controls collapsing.
