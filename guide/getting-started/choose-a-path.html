Choose a path

Daemonloom spans product design, agent lifecycle, external capabilities, and bounded execution. You do not need to learn every layer before the part relevant to you.

For a route tailored to your responsibility, start with Find your route. It covers evaluators, product leaders, security reviewers, architects, developers, integrators, operators, auditors, workforce designers, and harness implementers.

If you have ten minutes, read the system map, then trace one governed action. The first explains ownership; the second shows why those boundaries matter during a real external effect.

When you want to check whether the map has stuck, take the interactive knowledge quiz. Its twenty-five source-linked questions cover architecture, authority, connectors and protocols, the Agent lifecycle, operations, and evidence. Progress stays only in your browser.

I am evaluating the project​

Start with the system map, then check current status. Together they separate the intended architecture from what is executable today.

The shortest useful sequence is:

  1. Welcome to Daemonloom — the product thesis and operating loop.
  2. System map — ownership and dependency direction.
  3. Trace a governed action — one visible write from intent to evidence.
  4. Governed work — the general operating loop.
  5. Current status — maturity without production shorthand.

I want to understand agent governance​

Read governed work and the trust model. Then continue to the AI Agent Platform for product policy and Agent for the provider-independent run lifecycle.

I want to use the coding harness​

Zwirn is Daemonloom's named coding harness. Open its standalone product overview. It begins with an engineering outcome and shapes a task-fit workspace, capability set, worker, decision boundary, and evidence plan around that work.

Then read Engineering workflows → Using the coding harness → Task studio → Current status. The route is for engineers using Zwirn across software, infrastructure, incidents, and complex problems. Implementation details are deliberately deferred to the final Technology page.

I want to integrate an external system​

Open the connector explorer to search the current public catalog. The catalog guide explains providers, operations, events, channels, and what catalog presence does—and does not—promise.

Continue to operation contracts when you need to interpret risk, effects, idempotency, interaction shape, or required capabilities.

Use Evaluate a connector for a practical checklist and a worked contract reading.

If your development deployment supplies the connectors binary, follow the Connectors CLI guide to start the personal-local daemon, connect Slack, Grafana, or Kubernetes, and inspect the effective operation and event surfaces.

Catalog versus service

The catalog artifacts exist today. The deployable Connectors platform that will resolve connections, grants, invocation, and durable event delivery remains pre-v1 work.

I want to understand execution isolation​

Read Substrate, then return to the system map to see why product policy, connector authority, and execution admission remain independent decisions.

I want the workforce product​

Guild is the downstream workforce product. It gives agents durable jobs, employment, organizational responsibility, reporting relationships, and evidence-backed progression without creating a second agent runtime.
