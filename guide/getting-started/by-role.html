Find your route

Daemonloom crosses product, runtime, security, integration, and operations concerns. Choose the question you are accountable for; each route ends with the current-status check that keeps intended architecture separate from working software.

Project evaluator​

You need to decide: whether the thesis is coherent and the implementation evidence matches its claims.

Read Introduction → System map → Trace a governed action → Current status.

Leave able to explain the product thesis, the independent domains, one end-to-end effect, and the largest remaining maturity gaps.

Product leader​

You need to decide: which customer policy and evidence belong in the product rather than the foundation.

Read Governed work → Decision gates → Revision lifecycle → AI Agent Platform.

Leave able to identify product-owned purpose, approval, evaluation, and promotion decisions.

Security reviewer​

You need to decide: whether authority can widen implicitly or controls can be bypassed on failure.

Read Trust model → Authority model → Failure and recovery → Connections and grants.

Leave able to enumerate the independent gates and their fail-closed behavior.

Platform architect​

You need to decide: where domain ownership ends and hosted composition begins.

Read System map → Deployment model → Contract versioning → Design principles.

Leave able to evaluate dependency direction, placement, and cross-owner compatibility.

Software and infrastructure engineer​

You need to decide: how to use the coding harness for software, systems, or incident work without losing control of scope, actions, and evidence.

Open Zwirn through its standalone product guide, then read Engineering workflows → Using the harness → Task studio → Trust and evidence → Current status.

Leave able to frame a task-fit work boundary, follow and control its live work, distinguish detected sources from admitted capabilities, and decide which evidence is required before accepting the result.

Connector integrator​

You need to decide: whether a reviewed capability contract covers the external work you need.

Open the connector explorer, then read Evaluate a connector → Operation contracts → Connections and grants.

Leave able to distinguish catalog presence, runtime service, connection health, and grant authority.

Infrastructure operator​

You need to decide: which capabilities, placement, health, and recovery guarantees a deployment can actually serve.

Read Substrate → Deployment model → Operational signals → Failure and recovery.

Leave able to identify refusal conditions and signals that indicate a lost guarantee.

Auditor or compliance reviewer​

You need to decide: which claims can be reconstructed from attributable evidence.

Read Evidence chain → Authority model → Decision gates → Contract versioning.

Leave able to distinguish intent, admission, attempt, observation, and promotion evidence.

Workforce product designer​

You need to decide: how durable jobs and organizational responsibility compose with the generic agent lifecycle.

Read Guild → AI Agent Platform → System map → Revision lifecycle.

Leave able to keep workforce meaning in the product while reusing governed foundation capabilities.

Provider or harness integrator​

You need to decide: how an external agent loop can be normalized without claiming controls the harness cannot provide.

Read the standalone coding harness guide → Technology → Trust model → Failure and recovery.

Leave able to identify the supported protocol subset, native hooks, surrounding authority, and process-level defense in depth.

Always finish with status​

Every route describes intended boundaries as well as implemented pieces. End with Current status and interpret “design-stage,” “walking skeleton,” “development contract,” and “complete phase” narrowly.
