Catalog guide

The connector explorer is a public projection of the canonical generated catalog artifacts. It answers a practical question: what reviewed capability surface does this connector declare?

The current snapshot contains provider metadata, the full catalogued callable operation set, model tool projection markers, input and output fields, effects, risk, idempotency, authentication modes, events, and channel bindings. It never contains credential values.

Three surfaces must not be conflated:

SurfaceMeaning
Vendor APIEverything described upstream, including shapes the catalog may intentionally refuse or cannot represent safely.
Callable catalogReviewed operations compiled into the canonical connector artifact and addressable through governed clients.
Model toolsA deliberately smaller subset eligible for direct projection into a model's context.

Catalog vocabulary​

Provider​

A provider is the compiled catalog template for one external system, such as GitHub or Slack. Its reverse-DNS authority becomes the stable namespace for operations and credential addresses.

The source connector declaration and its reviewed upstream specification compile into this provider document. Runtime behavior is subordinate to those canonical bytes.

Operation​

An operation is one invocable unit: a stable ID, contract, direction, risk, idempotency, effects, protocol driver, request facts, response schema, interaction shape, implementation placement, and required capabilities.

The explorer shows every operation in the callable catalog. A model tool badge marks operations eligible for direct model projection; catalog only means the operation remains callable through a governed client but is not placed in model context by default. Expand an operation to inspect its source service, endpoint shape, decision-relevant facts, inputs, and projected output fields.

Event​

An event is a declared provider-originated semantic fact, such as a Slack app mention. Event names form a closed set for grants; an undeclared event does not become valid because a webhook payload contains a similar string.

Channel​

A channel describes a provider-side transport supervised by Connectors without requiring a client process to remain connected. Event channels include signed webhooks, polling, and authenticated WebSockets. A session channel instead establishes a bounded bidirectional lifecycle and exposes its protocol, placement, implementation, and capability facts.

Protocol driver, interaction shape, placement, implementation form, and required host capability are separate catalog axes. See Beyond HTTP for SIP, direct sessions, and why a non-HTTP operation never fabricates an HTTP method or path.

Using the explorer​

  1. Search by connector name, operation ID, capability, or description.
  2. Narrow the provider list by protocol or to model-tool, read, write, or inbound surfaces.
  3. Select a provider to inspect its source services, authority, authentication modes, channels, and events.
  4. Switch between the full callable catalog and model tools, then search within the operation list.
  5. Expand an operation to see its contract facts and schema projection.

For a repeatable evaluation checklist and a worked GitHub example, continue to Evaluate a connector.

The search is entirely client-side over the committed public snapshot. No credential, account, or live Connectors service is contacted.

What catalog presence means​

A catalog entry means the surface is represented as reviewable canonical data and passes the catalog build's structural gates. It does not by itself mean:

  • the deployable Connectors service is production-ready;
  • a deployment has enabled the provider;
  • a user has established a connection;
  • a principal holds a grant for every listed operation;
  • the provider's upstream API is currently available;
  • every endpoint in the vendor's API has been catalogued;
  • every catalogued operation is projected as a model tool.

Catalog coverage is deliberately selective. A smaller reviewed surface with explicit effects is more useful to authorization than an unbounded raw API proxy. Model projection is narrower again: placing hundreds of tools into one model context would reduce both usability and control without making the underlying catalog more capable.

Data freshness​

The explorer is a generated snapshot of reviewed catalog contracts. Its displayed counts describe that snapshot; owner-issued Connectors artifacts remain the source of truth.
