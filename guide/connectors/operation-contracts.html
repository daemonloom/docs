Operation contracts

A connector operation is more than an HTTP method and path. It carries the closed facts that discovery, grants, approval policy, dispatch, and evidence need to agree on.

Decision-relevant fields​

FieldCurrent vocabularyMeaning
Directionread, writeCoarse caller intent; never a substitute for effects
Risklow, medium, high, destructiveOrdered review consequence used by grant and approval policy
Idempotencyidempotent, non_idempotent, conditionalWhether replay can safely repeat and under which declared condition
Effectsread, write, network, process, browser, filesystem, local_systemConservative execution consequences consumed as an explicit set
Interaction shapeunary, stream, subscription, leased_session, session_establishmentLifecycle shape, independent of transport
PlacementConnectors deployment, Substrate workload, or federated satelliteWhere the selected implementation must be served

Risk is not authorization. A low-risk operation still requires applicable route authority, a Connector grant, and a usable connection. A high-risk operation is not universally forbidden; it requires the customer's configured policy and decision path.

Why effects are declared​

Effects are read from the canonical document, never guessed from an operation name or derived from its protocol. A nominal “read” may still require network access, a browser, a process, or local filesystem interaction. Explicit effects let grants narrow the complete known set.

The grant model admits operations through predicates over declared facts—risk ceiling, effects subset, and idempotency—with explicit allow and deny exceptions. Deny has precedence.

Idempotency and retries​

  • Idempotent means repeating the same admitted request should not create an additional external effect.
  • Non-idempotent means a retry can repeat an effect and therefore needs deliberate handling.
  • Conditional means repeatability depends on a condition named by the contract.

This fact informs retry and approval behavior; it is not a promise that an unreliable network will deliver exactly once.

Protocol and placement are separate​

Interaction shape, protocol driver, placement, implementation form, and required capabilities are orthogonal. An HTTP operation can run at a satellite near a private endpoint. A future leased session can be served by built-in code or a separately attested workload without changing its product meaning.

Callers discover these facts but do not select runtime internals. If the declared capability or placement cannot be served, the operation is unserved or refused rather than dispatched through a weaker path.

Authentication metadata​

The catalog declares credential requirements, schemes, and subjects so a deployment knows how to establish a connection. It contains requirements, not values. During invocation, Connectors resolves the selected connection and places credentials only after authority and request-plan checks.

Clients hold authority, not vendor secrets.
