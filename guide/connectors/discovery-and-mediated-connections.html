Discovery and mediated connections

Some connected systems can reveal other configured services. Daemonloom treats that as a useful observation—not as permission and not as a new connection. A reviewed declaration can turn a known observation type into a candidate for its native Provider, after which an operator explicitly materializes and grants the Connection.

admitted parent read
        ↓
evidenced discovery observation ── unknown type → unsupported observation
        ↓ closed type mapping
connection candidate
        ↓ explicit materialization
native Provider Connection + independent Connector Grant
        ↓
direct route or fixed route through the parent Connection

Every arrow is a policy or lifecycle boundary. Nothing discovered inherits the parent's authority.

Keep the states separate​

StateWhat it saysWhat it does not say
Discovery observationA declared normalizer saw a bounded, evidenced fact in one admitted read.That the target is usable or authorized.
Connection candidateThe observation matches a closed mapping to a native Provider and possible route.That a Connection or Grant exists.
ConnectionA durable Provider instance has been explicitly materialized with a fixed route.That any caller may invoke it.
Connector GrantOne principal may invoke selected native operations over selected Connections.That Agent must expose the Connection to a worker.
Agent Endpoint GrantAgent may surface the materialized Connection to a task as an opaque Endpoint and admit endpoint-targeted operations.Access to the parent Provider, a datasource, or hidden route state.

An unknown observed type remains an unsupported observation. It never falls back to generic HTTP, an arbitrary proxy path, or a caller-filled URL.

The target keeps its native semantics​

Grafana is the first declared example. Its bounded data-source list can observe configured Prometheus, Loki, and Alertmanager services. A recognized item can become a candidate for the corresponding native Provider:

Observed Grafana typeNative ProviderFixed route adapter
prometheusPrometheusGrafana data-source proxy adapter
lokiLokiGrafana data-source proxy adapter
alertmanagerAlertmanagerGrafana data-source proxy adapter

A materialized Prometheus child publishes Prometheus operations and Prometheus semantics whether its route is direct or mediated by Grafana. Grafana-native operations remain on the parent. There is deliberately no general-purpose grafana.proxy capability. “Prometheus Provider” names the native API contract here; it does not imply direct backend transport, another credential, or another login.

A route transports; it does not grant​

A mediated route is fixed for the Connection's lifetime. It names an admitted parent Connection, an opaque Connector-owned resource binding, and a closed adapter. Initially, mediated routes are a single hop and parent and child share execution placement.

At invocation, Connectors plans the native target operation as a target-relative request. The adapter transports that request through the parent using the parent's admitted destination and credential custody. A missing adapter, stale observation, unavailable parent, placement mismatch, or nested route refuses or degrades the child. It never falls back to direct egress.

The child still needs its own current Connector Grant. That Grant permits only the child's native operations; it does not authorize arbitrary parent operations or proxy paths. The parent's Grant is not inherited by the child either.

Only value-free facts cross boundaries​

The public catalog can show that a Provider declares bounded discovery, the source operation, and its closed type-to-Provider mappings. It does not contain live observations or runtime bindings.

When Agent projects a materialized Connection, the harness may receive a safe label, qualified operation-provider identity, opaque Endpoint reference, boundary reference, owner-snapshot digest, and admitted endpoint-targeted operation descriptions. It does not invent a generic resource or datasource for that operation set. These stay inside Connectors:

  • parent credentials and credential references;
  • vendor data-source identifiers and backend URLs;
  • opaque resource bindings and proxy paths;
  • arbitrary destination or route selectors.

Active refresh is an ordinary Connector read. It requires both Agent-side discovery authority and normal Connector-side admission; a Discovery Grant is not a Connector Grant.

A future owner-declared datasource may project one admitted read into compact normalized entity rows instead of exposing the vendor envelope. Its pure value-projection IR is deliberately reusable by a future Workflows input/output modifier node; datasource bindings add read, paging, freshness, completeness, and provenance semantics without turning that transform into authority.

Reconciliation is part of the contract​

Each observation is bound to an evidence generation and digest. Refresh atomically replaces the observed set. A missing resource, changed type, changed parent generation, withdrawn mapping, or failed adapter makes dependent candidates stale and degrades any materialized child until reconciliation.

Audit can correlate the child Connection and Grant, parent generation, observation evidence, native operation, adapter, and final admitted destination without recording the hidden binding or credentials.

The first development slice​

The personal-local Connector now proves the complete Grafana path in development: a one-use, owner-only connect flow accepts a service-account token, verifies it with the bounded data-source read, reconciles recognized observations, and materializes mediated Prometheus, Loki, or Alertmanager Connections only where an independent target Grant is configured.

Target invocation first produces a mediated plan, then places the reviewed target-relative path beneath the sealed Grafana data-source route. The executor permits HTTPS JSON only, follows no redirects, uses no ambient proxy, and places only the parent Grafana credential. Unknown types stay unsupported.

This is deliberately a development proof. The credential is memory-only and disappears when the daemon restarts. The first explicit Agent Endpoint/operation projection exists, but active discovery and grant UX, durable keychain, secret-provider, and satellite-local custody remain later implementation work. There is no plaintext fallback.

The Connectors CLI guide shows the personal-local guided flow and the separate observation-inspection command without exposing the parent credential or mediated route.

Current maturity

The discovery and mediated-Connection model is accepted, and its first personal-local Grafana reconciliation, materialization, and mediated execution slice is implemented. Durable credential custody, broader deployment topology, and the general Agent Endpoint rollout remain open; this is not a stable or production-ready runtime claim.
